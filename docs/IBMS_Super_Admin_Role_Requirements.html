1. Executive Summary & Role Definition

In a multi-tenant enterprise billing and invoicing platform like IBMS, there is a fundamental architectural distinction between Platform Governance (Super Admin) and Workspace Administration (Tenant Admin):

Dimension Super Admin (SuperAdmin) Tenant Admin (TenantAdmin / Admin)
Operational Scope Global / Cross-Tenant Platform Control Plane (TenantId = null by default, with ability to inspect or switch into any tenant). Single Organization Workspace (Strictly bound to their single assigned TenantId).
Primary Responsibility Platform governance, tenant onboarding/suspension, quota limits, global IAM/RBAC, outbox/worker health, integration governance, and master blueprints. Managing their own company billing operations, customers, products, quotations, invoices, payments, credit notes, branding, and workspace staff.
Financial Data Access Governance & troubleshooting access across all tenants (with strict audit logging, support mode, and statutory immutability guardrails). Full operational CRUD within their own tenant boundary only.
Identity & Role Authority Can manage all users across all tenants, assign SuperAdmin / TenantAdmin roles, and configure global permission definitions. Can assign workspace roles (BillingManager, Accountant, User, Viewer) to users within their own tenant only.
Context Switching Global tenant context switcher allowing support inspection of any organization's workspace. None (locked to their single organization context).

2. Modules in the Super Admin Panel

The Super Admin panel encompasses 11 core modules spanning global governance, master configuration, asynchronous workers, and support mode:

M1: Executive Platform Dashboard

Real-time cross-tenant KPIs, system health telemetry, worker heartbeats, transactional billing velocity, and error counters.

M2: Tenant Lifecycle & Quotas

Onboarding wizard, automated master data provisioning, quota management (users, invoices, storage), and emergency tenant suspension.

M3: Global IAM & Session Governance

Dual-identity management (Platform BCrypt & Host SSO), cross-tenant user directory, password resets, and session kill-switch.

M4: Master RBAC & Permission Catalog

56+ fine-grained permissions, 8 built-in system roles, custom tenant role blueprints, and system role immutability protection.

M5: Statutory Defaults & Regional Blueprints

Master Country & Currency registry, GST/VAT tax calculation engine, sequential document numbering schemes with locks, and discount caps.

M6: Document Templates & Notifications

QuestPDF invoice layout designer, versioning, rollback, transactional notification templates with dynamic tokens, and email delivery logs.

M7: Background Jobs & Outbox Queues

Monitoring & manual execution of 6 worker jobs, transactional outbox dead-letter queue replay, bulk export jobs, and cleanup routines.

M8: Integrations & Webhook Governance

Third-party developer app registry, client API key issuance/rotation, webhook subscriptions, delivery latency, and event replay.

M9: Forensic Audit & Compliance

Cross-tenant immutable audit trail, before/after JSON diffs, actor attribution, IP tracing, mandatory change reasons, and compliance export.

M10: Cross-Tenant Support Inspector

Tenant Context Switcher (X-Tenant-Id) allowing audited diagnostic inspection of customers, products, quotations, invoices, and payments.

M11: Data Retention, Archival & Tenant Offboarding / Purge

Complete encrypted tenant data export packages, statutory 7-8 year tax retention enforcement, and audited tenant offboarding.

4. Core Validations, Security Guardrails & Workflows

Security Rule 1: Last Super Admin Lockout Prevention
A Super Admin cannot delete their account, set their status to Inactive, or remove their own Super Admin role if they are the last active Super Admin in the system (Count(Active SuperAdmins) > 1 enforced).
Security Rule 2: Tenant Context Resolution (TenantId = null Fix)
For global endpoints (/api/users, /api/roles, /api/v1/background-jobs), TenantId = null returns cross-tenant data. For tenant-scoped endpoints (/api/Audit), the backend must resolve TenantId from query param → X-Tenant-Id header → JWT claim → fallback to Tenant 1, eliminating 403 Forbid errors for Super Admin.
Accounting Rule 3: Statutory Immutability of Issued Financial Documents
Even as Super Admin, issued/paid invoices, credit notes, and payments cannot be hard-deleted or renumbered. Corrections must use formal Void/Cancel workflows or Credit Notes with mandatory justification reasons.

6. Key Discussion Questions for Team Alignment
